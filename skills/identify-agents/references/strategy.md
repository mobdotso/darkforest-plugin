# Investigation strategy

These methods follow the [September 5 findings](experience.md). Use the
[source register](sources.md) to select known examples and comparison cases.

## Find task material

Search distinctive questions, answer/program combinations, table values, and
complete query objects. Keep literal and normalized forms. A full task match
can identify benchmark derivation; a shared answer passage may come from an
ordinary public source. Follow matches into surrounding records and histories.

Calibrate each query family against a known readable example on the same route
or index. Record the query, inspected fields, date, pages or results examined,
and whether the control was recovered. Treat inaccessible surfaces and missed
controls as coverage limits. Check earlier reporting before calling a host new.

## Reconstruct the object and chronology

Preserve raw bodies, URLs, revision IDs, retrieval times, and hashes before
normalizing. Keep underlying query identity separate from its transport.
Unwrap recognized encodings with explicit rules; preserve repeated keys,
filters, formats, and unknown parameters. Sort set-like values only where the
endpoint semantics justify it. Check both expected equivalences and cases that
must stay distinct before applying a normalizer broadly.

For split payloads, preserve fragment order and rendering changes, decode as
data, and check integrity and decoded hashes. For revision histories, compare
first additions and body changes. Keep event time, publication time, metadata
time, and capture time distinct, including clock uncertainty.

Group identical bodies, mirrors, and repeated revisions before counting
independent observations. Report object and body counts alongside page counts.
An earlier occurrence can change the direction of a proposed source relationship.

## Test information use and alternatives

Read a proposed source and successor together. Identify source-specific task
constraints, results, next steps, or schedules, then show which were retained
or transformed. Link collections can nominate candidates without establishing
operational use. Explicit branches with distinct downstream work deserve
follow-up, including another hop to test whether specialization persists.

Record whether shared context was available and how ordinary copying, scripts,
human collaboration, or a common source could explain the sequence. Separate
adjacent replies from elapsed time. Stored requests establish what was written;
captured responses or execution records are needed to assess what ran.

Keep content identity, information reuse, and actor attribution as separate
conclusions. Names, network labels, shared hosts, and model self-descriptions
can guide research while leaving the operator unresolved.

## Evaluate a method before generalizing

Freeze the matching rule and selection procedure before examining held-out
objects, copy groups, or ordinary controls. Compare with a simple baseline.
Report the unit measured, numerator, denominator, review coverage, and errors.
Separate synthetic parser fixtures, retrieval yield, semantic eligibility, and
evidence about actors: improvement in one does not establish the others.

When a control reproduces the proposed signal, update its interpretation and
the search priority. Preserve useful retrieval methods while testing stronger
evidence. Choose the next observation that could change the explanation, and
carry corrections forward into the source record.
