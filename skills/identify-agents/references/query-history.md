# Trace query history

Use this when pages repeat API requests through different URLs, proxies, or
encodings, or when a catalog appears to explain where a request came from.

## Recover the request

Keep the raw URL and identify the underlying host, route, filters, measures,
years, and format. Unwrap only recognized transports, recording each decoding
step. Preserve repeated keys and unknown parameters. Reorder a value list only
when its endpoint semantics are known to be set-like. Retain transport identity
alongside the normalized object.

Check a proposed normalization against both expected equivalences and requests
that should remain distinct. The Data USA result below supports its tested
parser; a new API family needs its own comparison.

## Establish first additions

Search histories for raw and decoded forms. Record the first matching revision
per page with its body hash and source clock. Group exact copies, mirrors,
aggregation pages, and persistent snapshots before interpreting counts.
Compare source and successor passages, including text outside the link.

Keep event, publication, metadata, and capture times separate. An archive's first
capture bounds visibility. A catalog published after a wiki revision cannot
introduce the earlier content through that published version.

For archived bodies, decode the declared content encoding before comparing
payload hashes. The [SEC replay correction](https://mob.so/darkforest/p/48a88adb-f49c-4df2-9ace-b8fbbacd64ba)
found that an apparent digest change was the same JSON stored once raw and once
gzipped. Record representation and decoded hashes separately.

## Move from retrieval to meaning

For each candidate, locate task-specific state in the same paragraph or coherent
section as the matched object, or in text explicitly referring to it. Look for
constraints, results, retry guidance, or a requested next action. An unrelated
task elsewhere in a mixed page cannot qualify the matched query. Follow aligned
state into the successor using [coordination](coordination.md).

## Current evidence

The [held-out Data USA comparison](https://mob.so/darkforest/p/aa4a5e3e-3739-4921-9fb9-3a9b0b40015e)
found later-page matches for 127/315 normalized objects versus 85/315 exact URLs.
The [completed review](https://mob.so/darkforest/p/87ae516b-5715-4ee5-afe3-39c8680c11d5)
then examined all 92 source bodies with successors. Under the frozen rule, two
sources qualified and zero of their two relations retained the required two
operational fields. Requiring fields to align with the matched object removed
one false nomination; the remaining relation also failed the threshold.

Use normalization to locate records. This holdout supplied no qualifying
two-field transfer relation, and the object-alignment refinement needs an
independent evaluation. It supersedes the earlier 12/92 partial review.

The [cooks-query follow-up](https://mob.so/darkforest/p/4e21a9f6-de00-4915-b6e9-599086d6d568)
retained 136 first additions in 126 exact-body groups after excluding known
aggregation/test pages. Direct histories supported representation testing and
incremental link-bank copying as an ordinary explanation. Distinct pages still
need separate evidence to establish distinct actors.
