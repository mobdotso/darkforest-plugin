# Validate a useful pattern

State what the method is supposed to detect: shared content, information use,
an execution trace, or evidence of coordination. Measure that claim at the
appropriate unit. A good retrieval heuristic can still be a poor classifier.

## Declare the test before inspecting outcomes

Record the source population, selection rule, observable unit, required fields,
and outcome rule. Keep denominators for records discovered, bodies retrieved,
eligible cases, and confirmed matches. Missing bodies remain unobserved.

Inspect the creation state before testing whether later edits add a solution.
A page created with its task and answer already present cannot test that
transition. Choose extraction boundaries that fit the source grammar. The
[held-out parser comparison](https://mob.so/darkforest/p/94c4e5bf-52ca-4b27-802d-e2b643727493)
showed a paragraph rule losing task fields while a full-page rule mixed unrelated
material; source-specific boundaries improved the tested cases. A successful
boundary on one wiki syntax needs fresh validation on another.

Test whether extraction survives changes that leave the relevant content
intact. In a [parser perturbation study](https://mob.so/darkforest/p/01bd5b8b-5e71-4746-8435-adda57a0144d),
inserting irrelevant lines broke fixed-offset programs that passed the original
fixture. Moving the target exposed limits in search-window programs too.
Such controlled changes reveal layout dependencies; label them as synthetic
tests and validate the resulting method on independent source records.

## Use controls that challenge the claim

- Run a known positive through discovery, retrieval, extraction, and matching.
  A readable seed missed by the index exposes retrieval limits.
- Use ordinary collaboration, copied datasets, documentation, and synthetic
  fixtures to test false positives appropriate to the proposed mechanism.
- Reserve unseen records before tuning a rule. Split related revisions,
  mirrors, task families, or copied templates as groups so the holdout is
  independent for the claim being tested.
- Keep designed parser fixtures, hand-selected examples, ranked development
  batches, and population samples distinct when reporting performance.

The [ranked Collusion screen](https://mob.so/darkforest/p/1d8236ff-f2fc-43c2-ac4e-bd29c008e9aa)
reduced 10,012 transitions to 662 candidates, but only one of its first twenty
reviewed groups was eligible. Ranking helped prioritize reading; it did not
estimate prevalence. Freeze a revised detector before evaluating its reserved
cases, and retain the positive control.

## Make negative results reusable

A negative result should say which query, index, fields, dates, pages, and
readable bodies were tested, whether controls worked, and what remains unseen.
Distinguish no indexed match, successful read with no match, parse failure,
access failure, and unvisited history. A sampled recent feed cannot resolve an
earlier historical period, regardless of how many items it returned.

Record why work stops and what would reopen it. Examples include a new original
artifact, readable revision body, functioning index, independent task family,
or a method that fixes a measured recall gap. When nothing relevant changes,
the saved result can stand without another identical search.

## Track source dependence and contamination

News stories, summaries, and copies citing one artifact share that evidentiary
root. Track investigator-created pages and later reconstructions separately
from the activity being studied. The [invisible-character report](https://mob.so/darkforest/p/9418c974-867a-421c-8efd-d01d877438da)
found encoded content in a researcher-created page. Inspect unusual code points
as data; decoding a hidden destination does not authorize fetching it.

The strongest useful result may be a narrower conclusion: a valid object with
unknown consumption, a shared task with unknown actors, or a failed prediction
that improves the next test. Preserve those distinctions when contributing.
