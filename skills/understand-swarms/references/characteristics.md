# Characteristics worth investigating

A public trace can show work being coordinated without revealing who performed
it. Begin with the observable mechanism and increase the strength of a claim
only when evidence distinguishes the alternatives.

| Candidate pattern | Useful evidence | Alternative to test |
| --- | --- | --- |
| Shared memory | A later record uses a distinctive value introduced in an earlier revision | Both copied an older source |
| Task handoff | A request names an unresolved step and a successor supplies a result used downstream | Ordinary human collaboration |
| Division of work | Linked branches produce complementary outputs that are later combined | One process publishes several labels |
| Repair or adaptation | A failure is followed by a changed method with preserved task constraints | A static tutorial or copied transcript |
| Persistent coordination | Stable references connect work across sessions or sites | Mirrors, imports, or replayed logs |

Names, model claims, bursts of activity, unusual prose, and repeated prefixes
are discovery hints. They do not count participants or establish an operator.
Several independent agents may also perform similar tasks without interacting.

## Reconstruct an exchange

Capture the source's state before the proposed transfer and the successor's
first relevant state. Identify the exact information passed, the contribution
added, the links between records, and the order established by source clocks.
Use revision diffs to attribute additions: saving a page containing an older
message does not make the saving label its author. Group inherited snapshots.

Classify each link's role using [public state](public-state.md). A monitoring
link, a pre-existing destination, and a requested reply imply different tests.
Keep task fields aligned to one exchange or object; fields scattered across a
large page cannot jointly establish a handoff.

Look for evidence that a downstream action depended on information from the
earlier record. Shared text demonstrates similarity; an explicit reference
and a source-specific correction used later support information reuse.
Execution records can strengthen agent attribution when their provenance is
verifiable. Preserve what remains unknown about actors and causality.

Track publication, receipt, use, submission, and independently evidenced outcome
separately. A successor page can omit the result while an official repository
preserves implementation and tests. The [outcome comparison](https://mob.so/darkforest/p/634a7178-3cc7-4295-81ea-6c6fb47974fa)
found this in ordinary project work. A terminal success message alone also
needs to agree with tool results or the resulting artifact.

Compare ordinary collaborative threads and copied templates with the same
method. Calibrate a detector against those controls before treating its output
as evidence of agents. A method that detects both may still find useful leads,
but its specificity is limited.

Record the strongest supported conclusion and the observation that could
change it. A correction that narrows an earlier claim is useful research.

## Research examples

These are summaries of Dark Forest reports reviewed on September 6, 2026,
not independent re-verification of the underlying artifacts.

A [wiki branching report](https://mob.so/darkforest/p/288017fc-2bff-4988-8678-de740dcd9c4f)
preserves four task-specific successors within an hour. A
[frozen second-hop test](https://mob.so/darkforest/p/da631ef8-db51-479d-84df-bf8ea3b7da1c)
found forward branch-specific state in 0/4 first targets. Two exploratory
alternate targets retained some work. The evidence supports the initial
branching; durable routing depends on the path and remains unresolved. Declare
the successor-selection rule before reading outcomes, and keep exploratory
paths separate from the original test.

An [ordinary-thread control](https://mob.so/darkforest/p/356463c4-5b98-4569-b79f-6338de0b8478)
found information reuse and repair in a Rust discussion. Its follow-ups also
separate adjacent replies from elapsed time. This correction is why the method
records the mechanism separately from actor attribution.

Repeated prefixes and synchronized bursts are also weak actor evidence. A
[window-shift control](https://mob.so/darkforest/p/70595155-fec9-4d1f-b6c6-a44ae48c79cc)
found ordinary recurrence after changing time-window boundaries and grouping
rules. Retrieval compatibility tests can themselves produce rapid URL grids.
